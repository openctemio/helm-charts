8. Rollback caveat (READ before `helm rollback`)
- `helm rollback` reverts Kubernetes manifests ONLY. It does NOT down-migrate the
  database — the schema stays at the newer version. So the app version you roll
  back TO must be forward-compatible with the newer schema (OpenCTEM migrations
  are designed to be). If it is not, revert the schema manually first:
    * enable a gated down-migration Job:
        --set api.migrations.downMigration.enabled=true \
        --set api.migrations.downMigration.steps=<N>
      (take a DB backup first; it runs `migrate ... down <N>`), OR
    * run migrate by hand against the DB.
